# Architecture and trust boundaries

```text
Human/API
  │ analyze (read-only)
  ▼
Manager workflow ──► EvidenceCollector ──MCP──► AWS API MCP ──► AWS
  │                     EC2 / CW / CE / Pricing
  │
  ├── deterministic Decimal analysis
  ├── dependency checks + scenarios
  ├── immutable proposal SHA-256
  ▼
Human approval boundary
  │ exact hash + expiry + approver + rollback flag
  ▼
Drift recheck ──► fixed executor ──MCP──► stop / modify / start only
  │
  ├── EC2 status verification
  ├── SSRF-protected HTTPS application check
  └── hash-chained audit + independent CloudTrail
```

The model may explain evidence and alternatives, but authorization is ordinary code.
Action names are a closed Pydantic literal, commands are generated by the state machine,
and IAM is the final authority. MCP data is treated as evidence rather than instructions.

## Current boundary

One account/region per run; one explicit standalone EBS-backed On-Demand instance; one
human-selected target type. ASG, Spot, instance-store, architecture migration, deletion,
commitment purchases, storage mutation, and cross-account write operations are blocked or
deferred.
